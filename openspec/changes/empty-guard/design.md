# Design: empty-guard

## Context

Компонент `NewCardForm` (`client/src/components/NewCardForm/NewCardForm.tsx`) содержит форму добавления карточки с полем ввода и кнопкой «Добавить». При пустом или пробельном названии форма молча игнорирует нажатие (строка 22–24 `handleSubmit`), но кнопка визуально не отличается от обычного состояния.

Дельта-спецификация (`openspec/changes/empty-guard/specs/new-card-form/spec.md`) определяет три требования:
- **REQ-1** (delta): не создавать карточку при пустом/пробельном названии — уже реализовано через `if (!title.trim()) return;`.
- **REQ-2** (delta): создавать карточку при непустом названии — уже работает без изменений.
- **REQ-3** (delta): кнопка «Добавить» SHALL выглядеть неактивной, пока название пустое или из пробелов.

Требуются изменения только в визуальном отображении кнопки.

## Goals / Non-Goals

**Goals:**
- Сделать кнопку «Добавить» визуально неактивной при пустом/пробельном названии.
- Сохранить существующее поведение мутации и обработки ввода без регрессий.

**Non-Goals:**
- Изменение API-слоя (`client/src/api/cards.ts`) или типа `Card` (`client/src/types/card.ts`).
- Добавление сообщений об ошибке, тостов или других элементов обратной связи.
- Изменение `BoardColumn`, `BoardHeader` или `App.tsx`.
- Реализация удаления карточек.

## Decisions

### Решение 1: Расширение атрибута `disabled` кнопки (выбрано)

**Описание:**
Расширить существующий проп `disabled` кнопки, добавив условие `!title.trim()`:

```tsx
<button
  className={styles.button}
  type="button"
  onClick={handleSubmit}
  disabled={!title.trim() || mutation.isPending}
>
```

Файл: `client/src/components/NewCardForm/NewCardForm.tsx`, строка 42.

**Почему подходит:**
- CSS-файл `NewCardForm.module.css` уже содержит правило `.button:disabled` (строки 38–40) с `opacity: 0.5` и `cursor: not-allowed` — визуальная неактивность уже описана в стилях.
- Атрибут `disabled` семантически корректен: действие действительно недоступно при пустом названии.
- Минимальное изменение — одна строка в одном файле.
- Не требует создания новых CSS-классов или inline-стилей.

### Решение 2: Добавление CSS-класса `.button--empty`

**Описание:**
Ввести условный CSS-класс на основе состояния `title`:

```tsx
<button
  className={`${styles.button} ${!title.trim() ? styles.buttonEmpty : ""}`}
  ...
>
```

И добавить в CSS:
```css
.buttonEmpty {
  opacity: 0.5;
  cursor: not-allowed;
}
```

**Плюсы:**
- Не блокирует кнопку на уровне DOM — `onClick` остаётся вызываемым (хотя `handleSubmit` всё равно вернётся).
- Классический BEM-паттерн, совместимый с CSS Modules.

**Минусы:**
- Требует изменения JSX (шаблонная строка в `className`) и добавления нового CSS-селектора.
- `onClick` остаётся активным на уровне DOM, что может быть запутано для скринридеров.
- Дублирует поведение `:disabled`, которое уже есть в проекте.

### Решение 3: Inline-стили

**Описание:**
Применить условные inline-стили напрямую:

```tsx
<button
  style={!title.trim() ? { opacity: 0.5, cursor: "not-allowed" } : {}}
  ...
>
```

**Плюсы:**
- Не требует изменений в CSS-файле.

**Минусы:**
- Смешивает стили с логикой компонента.
- Повторяет значения `opacity: 0.5` и `cursor: not-allowed`, которые уже есть в CSS (нарушение DRY).
- Сложнее поддерживать при изменении дизайн-системы.

### Сравнение

| Критерий | Решение 1 (`disabled`) | Решение 2 (`.button--empty`) | Решение 3 (inline) |
|----------|----------------------|---------------------------|-------------------|
| Изменений кода | 1 строка | JSX + CSS | JSX |
| Семантика | ✅ нативный атрибут | ⚠️ onClick остаётся активным | ⚠️ нет семантики |
| Переиспользование стилей | ✅ `:disabled` уже есть | ❌ новый класс | ❌ дублирование |
| Доступность (a11y) | ✅ фокус убирается | ⚠️ фокус доступен | ⚠️ фокус доступен |
| Совместимость с `:hover` | ✅ `:disabled` переопределяет | требует `:not(.button--empty)` | требует `:not(...)` |

**Выбранное решение:** Решение 1 — расширение атрибута `disabled`. Оно требует наименьшего количества изменений, использует уже существующее CSS-правило, семантически корректно и правильно работает с доступностью.

## Risks / Trade-offs

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Отключение кнопки меняет фокус пользователя | Пользователь,-tab-навигирующий к кнопке, может пропустить её | Кнопка остаётся в DOM-порядке; `disabled` — стандартное поведение, ожидаемое от пользователей |
| `title.trim()` вызывается дважды (в `disabled` и `handleSubmit`) | Минимальная производительность, не критично | Можно вычислить `const isEmpty = !title.trim()` и использовать в обоих местах для читаемости |
| Изменение только `NewCardForm.tsx` и `NewCardForm.module.css` | Нет рисков регрессии в других компонентах | Дельта-спецификация ограничивает область изменения одним компонентом |

## Migration Plan

Изменение не требует миграции данных или конфигурации.

**Шаги:**
1. Изменить проп `disabled` в `client/src/components/NewCardForm/NewCardForm.tsx` (строка 42).
2. Проверить визуальное состояние кнопки при пустом и непустом вводе.
3. Убедиться, что поведение при непустом вводе не изменилось (карточка создаётся, поле очищается).

**Rollback:** Откат к предыдущей версии — revert одной строки в `NewCardForm.tsx`.

## Open Questions

Нет. Все решения определены на основе существующей архитектуры и требований дельта-спецификации.
